# 0023. Плотность рабочего стола подбирается по высоте экрана, чтобы Gboard не делилась пополам

- Статус: принято
- Дата: 2026-11-04
- Источники: стенд 04.11 (эмулятор ГУ 1280×720, Gboard 18.5), `DesktopGeometryPolicy.density`, `CarConfigMath.BASE_DPI`

## Контекст

Дисплей рабочего стола был 1280×720 при 160 dpi, короткая сторона 720 dp. Gboard считает такой экран планшетом
и делит клавиатуру на две половины. Набирать адрес в поиске навигатора неудобно.

## Решение

По умолчанию (`desktop_density` = 0) плотность считается от высоты: короткая сторона около 576 dp, не меньше 160 dpi.
Для 720 это 200 dpi, для 480 остаётся 160. На стенде при 200, 213 и 240 клавиатура целая, при 160 делится.

Наш лаунчер свёрстан в пикселях, его плотность не меняет. Крупнее становятся клавиатура, системные окна и чужие
приложения в окнах.

«Масштаб карты» навигаторов на своём хосте считается от постоянных 160 dpi, а не от плотности дисплея. Иначе
выбранная ступень поплыла бы вместе с ней.

## Альтернативы

- Выключить «Разделённую клавиатуру» в настройках Gboard. На экране телефона пункта нет. На экране ГУ он есть,
  но после выключения и перезапуска Gboard клавиатура всё равно делится.
- Своя клавиатура для поиска навигатора: работы много, а в чужих приложениях всё равно осталась бы Gboard.

## Последствия

- Чужие приложения в окнах рабочего стола крупнее, в маленькое окно влезает меньше.
- Порог 600 dp взят из поведения Gboard на стенде. Другие клавиатуры могут вести себя иначе.
