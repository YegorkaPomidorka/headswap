# 0006. Обходы под ГУ включаются флагом по каналу/модели, а не глобально

- Статус: принято (правило уточняется, см. «Последствия»)
- Дата: 2026-10-14 (PR #18, #10), до 2026-10-30 (PR #113)
- Источники: PR #10, #18, #56, #72, #89, #113, кейсы h93, `aa/AaBridge.kt:192-214`, `:412-424`, `:642-710`

## Контекст

В 1.1.6 был глобальный keepalive на PAUSE. Правка под Mazda и VW ломала Honda (h93). Разные ГУ рвут связь по разным
причинам, а опробовать обход можно только на живой машине.

## Решение

Каждый обход — отдельный флаг в `AaBridge`: `huDesayG6S`, `huVw20082120`, `huVwBt1420`, `huVwCns2Delphi`,
`huHyundaiCn7`, `huHonda20772121`, `huMazda20622111`, `huMobisNx4c` (`AaBridge.kt:192-214`). ГУ опознаётся по
`HU_INFO` (manufacturer/model/product) или `STATISTIC_INFO.channel` (`:642-710`). Флаги сбрасываются при каждой
новой сессии, пока ГУ не представится заново (`:412-424`). Обход действует только на своём ГУ, в тестовых сборках тоже.

## Альтернативы

- Глобальный keepalive (1.1.6) — ошибка, разнесён по ГУ в PR #18.
- Самообучаемый `PauseKeepalive` из стороннего форка — отложен после 3.0.0.

## Последствия

- Напряжение имя → канал → бренд. Список «VW BT NNNN» по именам не масштабируется: PR #113 перешёл на канал
  с исключением (BT 1420) и на пару «канал + имя» (`AaBridge.kt:682-690`, `VW_ID_IDR_LIMIT_HUS`).
- Новое правило в корневом CLAUDE.md: «Car-brand fixes apply to all models and channels of that brand unless told
  otherwise». Оно расходится с «строго одно ГУ» из PR #18/#113 и с P2P-rejoin в PR #68, который назван общей логикой.
  Как Егор разводит эти правила на практике (когда бренд, когда канал): Почему: ? (спросить Егора)
- Новый обход добавлять с логом при включении и сбросом на новой сессии; не менять поведение остальных ГУ.
