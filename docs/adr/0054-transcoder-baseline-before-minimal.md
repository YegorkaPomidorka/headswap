# 0054. Энкодер держит Baseline до последнего, «минимальный формат» только в самом конце

- Статус: принято
- Дата: 2026-11-21
- Источники: лог `headswap-20261121-161249` (VW, Desay DS03H channel 20082123, Xiaomi 220333QNY, Android 13,
  4.3.0, рабочий стол 1024×600), кейс h841 (то же в заглушке), `aa/AaTranscoder.kt`, `VideoSource.configureFallback`

## Контекст

У `AaTranscoder` после неудачных шагов 0 (Baseline+VBR+realtime+low latency) и 1 (Baseline+VBR без B-кадров)
шёл сразу «минимальный формат» без профиля. OMX.qcom на Xiaomi 220333QNY отвергает оба первых шага
(`IllegalArgumentException`, `0x80001001`), а без профиля отдаёт High с level 1.0 (`67 64 00 0A`).
DS03H High не декодирует: на ГУ замерзает последний кадр заглушки, поверх каша из блоков, тачей нет.
Заглушку от этого уже лечили (h841): там Baseline без режима битрейта, level 3.1, проходит на том же энкодере.

## Решение

Перед «минимальным форматом» добавлены два шага: только `KEY_PROFILE=Baseline` с уровнем по размеру кадра
и fps (`avcLevelFor`, таблица A-1), потом Baseline без уровня. Режим битрейта и B-кадры в этих шагах
не задаются. `tuning=nobase` их пропускает.

## Альтернативы

- Флаг под DS03H. Отказ: High без уровня опасен для любой ГУ CarLife, а шаг ничего не меняет там, где
  проходят шаги 0 и 1.
- Брать уровень 3.1, как в заглушке. Для рабочего стола 1080p он мал, поэтому уровень считается.

## Последствия

На OMX.qcom без шагов 0/1 битрейт идёт в режиме энкодера по умолчанию (обычно VBR). В логе видно по
`encoderNote`: `baseline+level3.1+repeat100ms`.
