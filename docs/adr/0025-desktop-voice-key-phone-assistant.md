# 0025. Кнопка голоса в режиме рабочего стола открывает помощника телефона

- Статус: принято
- Дата: 2026-11-05
- Источники: поездка 04.11 на Vezel (лог 21:16:42, 21:16:51), `AaBridgeCore.phoneAssistant`, `dex/PhoneAssistant`

## Контекст

В режиме рабочего стола кнопка голоса на руле уходила в теневую AA как KEYCODE_SEARCH. Теневая AA работает без экрана
и без микрофона, её задача — стрелки навигации. Ассистента в ней не видно и не слышно, кнопка молчала.

## Решение

В режиме рабочего стола кнопку (MODULE_CONTROL VR=1 и VR_START с руля) получает помощник, назначенный в системе
Android, через intent VOICE_COMMAND, запасной вариант — ASSIST. Какого помощника выбрать (Gemini, Алиса), решает
пользователь в настройках телефона. Своего списка ассистентов в Headswap пока нет. В режиме AA всё по-старому.

## Альтернативы

- `cmd voiceinteraction show`, как долгое нажатие питания: нужен ACCESS_VOICE_INTERACTION_SERVICE, у shell его нет.
- Дать теневой AA экран и микрофон: тогда это уже полная проекция, архитектура рабочего стола ломается.
- Свой голосовой интерфейс на рабочем столе: отдельная большая фича.

## Последствия

Окно помощника открывается на телефоне, а не на ГУ. Работает ли запуск при заблокированном экране и чей микрофон
слушает помощник (машины по BT HFP или телефона), на машине пока не проверено.
