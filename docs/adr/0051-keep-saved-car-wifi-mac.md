# 0051. Уже поднятый Wi-Fi машины не переподключать через specifier

- Статус: принято
- Дата: 2026-11-18
- Источники: лог `logs/headswap-20261118-192918` (VW ID.Unyx, Samsung SM-S918B, Android 17),
  `link/car/CarNetwork.kt`, `CarNetPolicy.sameCarLan`, ревью PR 250

## Контекст

На Unyx каждое беспроводное подключение заводило в меню машины новый CarLife-девайс с тем же именем телефона.
В логе 13:13 телефон уже был в сети ГУ (`10.173.189.63`), `sta-concurrency local=false`. Сразу после
`car-request` эта сеть пропала и specifier поднял другую (`10.173.189.58`). У WifiNetworkSpecifier нет
настройки MAC: это отдельный профиль, и «MAC пристрою» в сохранённой сети на него не действует.
Дальше по дню сессии шли то с `.63`, то с `.58`.

## Решение

Сеть машины узнаём по адресам, не по имени. После удачного входа запоминаем IPv4 телефона, длину
префикса и шлюз (`CarWifi`). На Android 13+ SSID из снимка `NetworkCapabilities` пустой, а разрешение
на геолокацию возвращать не будем.

Если текущий Wi-Fi уже в этой подсети (префикс не короче /16) или у Wi-Fi без интернета тот же шлюз,
сеть держим через `requestNetwork` с `TRANSPORT_WIFI` и без `NET_CAPABILITY_INTERNET`, без specifier.
Чужая сеть в этом колбэке отпускается, и тогда идёт specifier. Пока у Wi-Fi без интернета нет IPv4,
ждём DHCP до 4 с, а не открываем второе подключение. `onAvailable` уходит через handler, чтобы не
зайти в запрос повторно из `restartForCarNet`. Specifier по-прежнему нужен, когда запомненной подсети
нет или телефон в ней ещё не сидит.

## Альтернативы

- WifiNetworkSuggestion с постоянной случайной MAC. Подсказка не умеет заводскую MAC, а сеть ГУ без
  интернета сама часто не подключается. Второй профиль рядом с уже сохранённой сетью дал бы ещё одну MAC.
- Менять MAC у specifier через скрытое поле. На targetSdk 37 скрытый API приложению закрыт.

## Последствия

Первый вход, когда подсеть ещё не запомнена или телефон не в сети машины, по-прежнему идёт через
specifier и может один раз создать новый девайс. Следующие поездки держат ту же подсеть и ту же MAC.
Имя сети в WL не пишется; удержание видно по `held=lan`. Лог до этой правки такого маркера не содержит:
там смена `10.173.189.63` на `10.173.189.58` как раз баг.
