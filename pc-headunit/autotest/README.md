# Автотесты UI на стенде ГУ

Python прокликивает экран Headswap на эмуляторе ГУ CarLife (`carlife_hu.py`) и проверяет его без LLM:
текст через OCR Windows, картинку через сравнение с эталоном. Телефон подключается по USB, как для `stand.ps1`.

## Что нужно

- телефон по USB с отладкой; на Xiaomi ещё «Установка через USB» в настройках для разработчиков;
- `ffmpeg` в PATH, `opencv-python`, `numpy`;
- OCR: пакеты pywinrt и русский язык распознавания в Windows:
  `pip install winrt-runtime winrt-Windows.Media.Ocr winrt-Windows.Graphics.Imaging winrt-Windows.Storage.Streams winrt-Windows.Foundation winrt-Windows.Foundation.Collections winrt-Windows.Globalization`.
  rapidocr не подходит: его модели читают кириллицу как латиницу («Настройки» → «HacTpoMK»).

## Запуск

Из `pc-headunit`:

```
python -m pytest autotest/scenarios -v                 # сценарии
python -m pytest autotest/scenarios -v --update-refs   # переснять эталоны
python -m autotest dump "text Настройки" dump back     # разведка экранов без pytest
```

Подготовку телефона (сборка smoke, установка, `bridgeMode`, активация, `adb reverse`) делает
`stand.ps1 -PrepareOnly`. Флаг `--no-prepare` её пропускает.

Отчёт пишется в `out/autotest-<время>/`:
- `steps/NN-*.png` — кадры по шагам;
- `actions.log` — что нажималось;
- `carlife_hu.log` — лог эмулятора;
- лог телефона;
- `fail/*-actual.png` и `*-diff.png` — кадр и разница при несовпадении с эталоном.

## Сценарий

```python
def test_settings_opens(stand):
    stand.tap_text("Настройки")
    stand.wait_text("Вид")
    stand.check("settings", masks=[STATUS])
```

| Метод | Что делает |
|---|---|
| `tap(x, y)`, `long_press`, `swipe(x1, y1, x2, y2)` | касания в пикселях видео: кадр 1:1, без пересчёта |
| `back()`, `home()`, `voice()`, `key(code)` | кнопки ГУ |
| `tap_text("фраза")` | тап по надписи |
| `wait_text`, `wait_no_text`, `has_text`, `text()` | работа с текстом экрана |
| `check("имя", masks=[...])` | сравнение с `refs/<hu>-<W>x<H>/имя.png` |
| `tap_image("иконка")` | поиск картинки `refs/.../icons/иконка.png` |
| `settle()` | ждёт, пока экран перестанет меняться |
| `shot("имя")` | кадр в отчёт |

Текст сравнивается без регистра, без диакритики (`ё` = `е`, `è` = `e`) и с кириллическими и латинскими
буквами-двойниками как одной буквой. OCR иногда пишет «домой» со строчной, а в «1280х720» ставит кириллическую «х».

## Языки

Тексты в сценариях — ключи строк приложения: `stand.R.l_sec_look`, `stand.R("l_battery", 80)`. Их читает
`strings.py` из `android/app/src/main/res/values*/strings*.xml`. Если в языке нет ключа, берётся английский, как в
Android. Прогон по языкам:

```
python -m pytest autotest/scenarios -v --lang ru,en,fr
python -m pytest autotest/scenarios -v --lang all      # en ru ar fr zh-CN
```

- Язык ставится командой `cmd locale set-app-locales`, а приложение перезапускается и активируется заново: от языка
  зависят набор навигаторов и раскладка. На смену языка уходит ~20 с.
- Эталоны лежат по языкам в `refs/<hu>-<W>x<H>/<язык>/`, иконки общие в `refs/<hu>-<W>x<H>/icons/`.
- Если фразу не нашли, а на экране есть её начало с многоточием («Nothing is playi...»), тест падает с «обрезан
  многоточием».
- OCR Windows: свой язык нужен для каждого языка приложения (`python -c "from autotest.ocr import available_ocr;
  print(available_ocr())"`). Французский без пакета читает английский движок: он путает буквы с акцентами, поэтому
  допускается одна ошибка на фразу. Для арабского и китайского запасного движка нет. Пакеты ставятся в PowerShell
  от администратора:
  `Add-WindowsCapability -Online -Name "Language.OCR~~~ar-SA~0.0.1.0"` (и `zh-CN`, `fr-FR`).
- Заглушка моста («Запускаю рабочий стол…») зашита по-русски на любом языке, `wait_ready` ищет её русским OCR.

## Что надо знать о стенде

- Первый кадр — заглушка моста «Запускаю рабочий стол…». Касания в это время мост не принимает, в логе телефона их нет
  совсем. `start()` ждёт настоящий экран (`wait_ready`).
- Лаунчер помнит экран прошлого запуска, а шестерёнка работает как переключатель: если стенд поднялся на «Настройках»,
  тап по ней их закроет. Поэтому фикстура перед каждым сценарием жмёт HOME.
- Кадр свежий: экран меняется через ~0,1 с после тапа, `settle()` после тапа совпадает с последним кадром потока.
  Декодер ffmpeg запущен с `-threads 1`.
- Скорость: после тапа стенд ждёт первый изменившийся кадр (до `change_wait` 0,6 с), потом `quiet` 0,3 с тишины.
  Повторный `settle()` без новых кадров возвращается сразу. Шаг «тап + поиск текста» занимает ~0,7 с, тап, который
  экран не меняет (HOME на главном), ~1 с. Пилот: 28 с → 16 с, из них ~6 с старт стенда.
- Анимации Android на время прогона выключаются (`settings put global *_scale 0`), после `stop()` возвращаются;
  `--animations` оставляет их. Xiaomi без пункта «Отладка по USB (настройки безопасности)» это запрещает: стенд пишет
  в `actions.log` «animations stay on» и едет с анимациями.
- Smoke и рабочий Headswap не активируются одновременно: shell делегирует права только одному приложению. Перед
  стендом рабочий надо остановить (`adb shell am force-stop com.yegorkapomidorka.headswap`).

`check` считает пиксель изменившимся, если разница больше `tol` (24), а экран совпавшим, если таких пикселей не
больше `max_ratio` (1 %). Часы и уведомления закрывать масками `(x, y, w, h)`.

Если эталона нет, `check` его создаёт, а тест помечается skipped («эталон создан»). Новый эталон надо посмотреть
глазами и закоммитить. Эталоны зависят от профиля ГУ, размера экрана, темы и цветов десктопа. Перед съёмкой
эталонов тему и цвета фиксировать.
